# 读写卡功能设计蓝图

状态：**设计阶段，未实现**——硬件还没到货，这份文档记录已经讨论定下来的交互设计，等 PN532 到手后照此实现。

## 页面结构

"设备"和"读写卡"合并成一个页面：连接管理、卡片识别、读写操作都在同一处，不需要跨页面同步连接状态。侧边栏最终大致是"读写卡"（合并后的主功能页）+ "设置"。

## 卡片类型识别

放卡后通过 `InListPassiveTarget` 返回的 SAK（SEL_RES）判断类型：

- `0x08` → Mifare Classic 1K
- `0x18` → Mifare Classic 4K
- `0x00` → Mifare Ultralight / NTAG 系列

识别结果决定"读写卡"页面展示哪一套操作面板，用户不需要手动选卡片型号。

## Mifare Classic 链路（扇区 + 密钥认证）

```
放卡 → 识别为 Classic → 逐扇区尝试认证
  ├─ 用内置常见密钥字典自动试（FFFFFFFFFFFF / A0A1A2A3A4A5 / D3F7D3F7D3F7 等）
  ├─ 试不出来的扇区标"未解锁"，允许手动填密钥补认证
  └─ 每个扇区认证结果实时显示（绿=已解锁，灰=未解锁），不是等全部试完才反馈

已解锁扇区 → 三个动作：
  ├─ 读取：显示 16 进制块内容，可导出 .dump/.json
  ├─ 写入：加载 dump 文件或手动改块 → 写入前弹二次确认（不可逆）
  └─ 拷贝：读源卡 → 提示"移除源卡，放上目标卡" → 写入前对比新卡 UID
           是否 == 源卡 UID，一样就中止并提示"这还是原来那张卡"
           （防止误操作把数据写回源卡本身）
```

密钥策略：默认用内置字典自动试，不需要每次都手动输入密钥。

## NTAG / Ultralight 链路（按页，多数免认证）

### 快速写入模板

标准 NDEF record 类型，统一走同一套写入逻辑：

- URL
- 纯文本
- WiFi 配置（SSID + 密码）
- vCard 名片
- 原始 hex（高级用户直接按页写）
- 电话号码 / 短信 / 邮件 / 地理位置 / 蓝牙配对（Handover）

### 批量写卡

配置好一份数据模板后，扫一张卡写一张卡，自动计数：

```
配置阶段：选模板 → 填内容 → "开始批量写入"
  ↓
【等待放卡】
  ↓ 测到卡
  ├─ 类型不是 NTAG/Ultralight？→ 报错提示，不计数，转到【等待离卡】
  └─ 类型对 → 写入
        ├─ 成功 → 计数 +1，短暂"✓ 写入成功"反馈 → 转到【等待离卡】
        └─ 失败 → 报错，不计数 → 转到【等待离卡】
  ↓
【等待离卡】（轮询 InListPassiveTarget 返回 None）
  ↓
回到【等待放卡】，循环
```

防重复计数只靠"等待离卡"这一步（同一张卡不拿走不会重复计数），不额外做 UID 去重记录。风险：如果轮询瞬间漏报一次"无卡"会误判卡离开过一次，但 PN532 轮询很稳定，实际基本不会发生。

"停止"按钮随时可以打断循环，整个过程不需要操作员中途手动确认。

### 密码保护（NTAG213/215/216）

- 通过 `AUTH0` + `ACCESS` + `PWD`(4字节) + `PACK`(2字节) 实现，**可逆**——随时能改密码或把 `AUTH0` 重置为 `0xFF` 解除保护
- 跟"标签管理"里的永久锁定是两套独立机制，可以同时存在
- **UI 上必须强提醒**：如果 `AUTH0` 覆盖范围包含密码配置页本身，改密码/解除密码也需要先用当前密码认证——忘记密码等于事实上锁死。设置密码完成后要弹出明确提示，不能设完就完事

## 标签管理（独立于"写入"的一组动作）

- **格式化**：初始化成空白 NDEF 结构
- **擦除**：清空数据但不锁定
- **永久锁定**：写保护，**不可逆**——防呆要比普通"写入前确认"更重，比如要求手动输入卡片 UID 后几位才能确认，不能点一下"确定"就完事

## Magic Card UID 克隆（独立于"拷贝"的新分支）

```
放卡 → 先探测是不是 UID 可写的 magic card
  （普通卡 UID 出厂焊死改不了；magic card 靠非标准的
   backdoor unlock 指令序列解锁 block 0 写入）
  ├─ 不是 magic card → 走"拷贝"流程（复制数据，UID 不变）
  └─ 是 magic card → 多一个"写入自定义 UID"选项，
     直接改 block 0（UID + BCC + SAK + ATQA）
```

注意：magic card 的 unlock 指令不在标准 PN532 命令集里，是非标准短帧（7-bit）backdoor 命令，需要用 `InCommunicateThru` 透传接口，跟其他功能走的 `InDataExchange` 是两条不同的路径，实现上单独一块。

## 明确推迟的范围

- ISO15693 / Type B / FeliCa 等 Type A 之外的制式支持——等 Type A 全链路（Classic + NTAG）跑通、有硬件验证过之后再评估要不要扩展。
